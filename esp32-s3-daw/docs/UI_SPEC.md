# Browser UI

`web/` — TypeScript 5.9, Preact 10, Vite 7; no UI framework beyond that. ~124 KB of JS
(43 KB gzipped) + 16.5 KB CSS, embedded in the firmware and served by the device itself, so the
DAW works on the device's own Wi-Fi with no internet.

## Principles

- **The device is the truth.** The UI renders the project it received (`welcome`, `patch`, `set`)
  and sends operations; it never assumes an edit succeeded beyond the optimistic redraw of the
  gesture in progress. Every view updates live when another browser edits.
- **Familiar to FL Studio users** on desktop (top transport bar, browser on the left, channel rack,
  piano roll, playlist, mixer, floating plugin windows, F5–F9), **FL Studio Mobile–style** on
  phones (bottom tab bar, one full-screen editor at a time, big touch targets).
- **Canvas for the dense editors** (piano roll, playlist, mini rolls), DOM for everything else.
  Pointer Events everywhere: mouse, pen and touch share one code path.
- **Plugins only describe controls.** Editors are generated from parameter descriptors (knobs for
  continuous values, segmented buttons / selects for enums, toggles for booleans, grouped). No
  plugin-supplied markup or script is ever loaded.

## Layouts

The layout switches at 760 px width (or < 1000 px with a coarse pointer):

**Desktop / tablet landscape** (`app/App.tsx`): top bar (menu, File, View, pattern / song mode,
transport, metronome, count-in, loop, tempo with tap, position, pattern selector, undo / redo,
panel toggles, CPU meter, master peak, connection), the browser (instruments, effects, presets,
patterns, projects) on the left, and stacked resizable panels: playlist, channel rack, piano roll,
mixer. The plugin editor is a draggable floating window.

**Phone** (`mobile/MobileShell.tsx`): compact transport row, pattern row, one editor at a time,
bottom tabs **Song** (playlist) · **Patterns** (channel rack, step pads) · **Piano** · **Mixer** ·
**Sound** (instrument editor of the selected channel) · **More** (projects, device, MIDI, settings).
Landscape keeps the tabs and gives the editor the full width.

Viewports covered by the automated screenshots (`tests/browser/screens.py`): 1920×1080, 1366×768,
tablet landscape 1180×820, phone portrait 390×844, phone landscape 844×390. Reviewed by eye after
UI changes; regenerated by `scripts/test-browser.sh` into `tests/browser/out/`.

## Interaction reference

| where | mouse / pen | touch |
|---|---|---|
| step sequencer | click toggles; drag paints (one undo step); right-click: step menu (velocity, probability, pitch, accent); shift / alt-click: accent | tap toggles, drag paints, long-press: menu |
| channel rack row | click name: plugin editor; right-click: channel menu (piano roll, rename, color, mixer track, replace instrument, fill / invert / shift / randomize / copy / paste, move, delete) | tap / long-press |
| piano roll | draw tool: click draws, drag moves, drag the right edge resizes, Ctrl-drag duplicates, right-click deletes, double-click: note properties; select tool: rectangle, shift adds; erase tool sweeps; slide tool draws slide notes; keys on the left preview; wheel scrolls, Ctrl-wheel zooms; lanes below for velocity / pan / release / fine pitch / probability | tap draws, drag moves, long-press: note menu, double-tap: properties, pinch zooms (horizontal / vertical separately), two fingers pan |
| playlist | draw: click places the chosen pattern / automation, drag moves, drag the edge resizes; slice tool; delete tool; ruler: click seeks, drag sets the loop; right-click clip: menu (duplicate, make unique, split at playhead, chop, delete, open pattern) | same with long-press menus, pinch / two-finger pan |
| automation editor (double-click / double-tap an automation clip, or right after creating one) | click adds a point, drag moves it (shift: time only), right-click deletes, drag the line or alt-drag bends the curve, double-click straightens; length and snap selectors | tap adds, drag, long-press: point menu |
| plugin editor preset menu | factory presets and "Mine (on the device)"; the disk button saves the current settings as a user preset; the Presets tab lists them with × to delete | tap |
| browser panel, Samples tab | Upload… (or drop files on the list), click a file: a new Sampler channel with it, × deletes; plugin editor: a sample selector per resource slot (missing files flagged); for a SoundFont, a "Font preset" menu of the presets inside the file (sets bank / program) | tap, the same |
| MIDI file | File > Import MIDI file… or drop on the playlist / sample browser: as a new project; the piano roll's import button, its menu or a drop on it: into the edited channel | More > Import a MIDI file…; piano roll menu |
| record button (top bar) | click arms / disarms MIDI recording; right-click: input grid | tap |
| device page | Device settings…: Wi-Fi, device name, admin password (asks for the admin login), Restart now after saving | tap |
| mixer | drag fader / knob (shift = fine, double-click = default), click effect slot opens it, right-click slot: bypass / move / remove, strip name: rename / color | drag, tap |
| knobs, faders, number fields | vertical drag, shift = fine, double-click = default (number fields: type a value) | vertical drag |

Keyboard: Space play / pause, F5 playlist, F6 channel rack, F7 piano roll, F8 browser, F9 mixer,
Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y undo / redo, Ctrl+S save, Ctrl+O open, K virtual keyboard,
Escape panic (all notes off); Z…M and Q…U rows play notes. In the focused piano roll: P / E / D
tools, Delete, Ctrl+A / C / X / V / D (select all, copy, cut, paste, duplicate), arrows move by the
snap / transpose (shift: octave), Q quantizes the selection.

## State and data flow

`app/state.ts` holds small stores (`conn`, `proj`, `catalog`, `live`, `ui`, `slots`) with a
selector hook (`useStore`); `live` (meters, position at 20 Hz) is separate so meters never
re-render editors. `app/actions.ts` turns gestures into protocol operations and undo entries
(`app/history.ts`). `app/protocol.ts` owns the WebSocket: handshake, reconnect with backoff, acks
with timeouts, patches, latency measurement.

Edits are applied optimistically where a gesture needs instant feedback (painting steps, dragging
notes and clips) and confirmed by the device's patch; a refused edit (`err`) shows a toast and the
next patch restores the truth.

## Accessibility

Buttons have titles / aria-labels, canvases have labels, focus outlines are kept, colors meet
contrast on the dark theme. Canvas editors are not screen-reader accessible (a list view of notes
and clips would be needed).

## Tests

`tests/browser/test_ui.py` (Playwright, Chromium, real pointer and touch input, checked against
`GET /api/project`): click and drag-paint steps, undo / redo, pattern switching, draw / move /
delete a note, place and move a clip, mixer fader, plugin knob, transport, two-browser sync,
phone step pads and piano roll. Runs against `daw-host` and against the firmware in QEMU.
